## 해석과 확인 사항

- 판매 부수는 알림 수가 아니라 수익내역의 정산건수를 합산합니다. 10월 15일 알림 1건에는 종이책 2부가 포함됩니다.
- 날짜는 실제 구매일이 아닌 부크크 수익내역 등록일입니다. 외부유통 보고 지연이나 취소·조정으로 달라질 수 있습니다.
- 정산완료는 지급 대상 확정이며 계좌 입금 완료를 의미하지 않습니다. 현재 지급목록에 지급완료 건은 없고 실제 계좌 입금은 미확인입니다.
- 부크크 안내상 자체 판매는 다음 달, 외부유통 판매는 다다음 달에 정산완료로 변경됩니다. 현재 12건은 모두 외부유통입니다.
- 11월 지급 예정 5,980원은 지급내역과 요청 메일로 확인했습니다. 지급내역의 이월·조정액 -5원의 상세 원인은 별도 확인되지 않았습니다.
- 10월 발생분 107,640원은 12월 지급 전 조정 전 예상액입니다. 새 지급내역과 정산 메일로 최종 확정해야 합니다.
- 11월 1~9일 등록된 수익은 0부·0원입니다. 미등록 판매나 남은 기간을 포함한 11월 전체 수익은 아직 예측하지 않습니다.
- 수익금은 저자 인세이며 도서 판매가의 합계인 매출액과 다릅니다. 이 페이지는 확인일 기준 수동 갱신 기록입니다.

메일의 “2026년 10월 수익금” 표기와 수익 원장의 판매 등록월을 분리해 관리합니다. 11월 지급 상세에는 9월 29일 종이책 1부가 직접 연결되어 있습니다. 이미 발급한 계산서의 대상 월과 금액은 메일 기준 기록을 유지합니다.

## 매월 갱신 절차

1. 부크크 알림 → 도서수익에서 알림을 열고 전체 수익내역과 대조합니다. 알림 받은 날과 읽은 날을 구분합니다.
2. 수익내역의 도서번호·형태·등록일·서점·정산건수·단가·총수익액·상태를 원장에 반영합니다. 같은 날짜와 금액의 다른 거래를 합치거나 삭제하지 않습니다. 로컬 id는 부크크 원본 거래번호가 아닌 관리용 키입니다.
3. 지급내역의 상세에서 대상 인세, 이월·조정액, 지급총액을 확인합니다. 상태가 정산완료여도 입금으로 처리하지 않습니다.
4. 새 정산 메일과 홈택스 발급 기록, 실제 계좌 입금을 각각 대조합니다. 미래 월 예상액에는 조정 전·미확정 표시를 유지합니다.
5. data/book-sales.json의 확인일·원장·지급 기록·사이트 대조 합계를 갱신하고 node scripts/build-book-sales.mjs를 실행합니다.
6. 생성된 HTML·CSV·이 보고서와 서비스 링크를 검토한 뒤 GitHub Pages와 기존 Codex Site를 모두 배포합니다.

개인 정산 증빙·계산서 승인번호·메일 원문 링크는 비공개 노션 관리 문서에 보관합니다. 공개 페이지에는 집계와 판매 원장만 게시합니다.
