03.15 · 04.05 / PYTHON & LINUX
로봇 코드를 실행할 수 있는 개발 환경 만들기
Ubuntu 가상환경 · VS Code · Python 함수와 클래스
3월 15일에는 스마트시티에서 자율주행 로봇이 맡을 역할을 살펴본 뒤, VMware의 Ubuntu 22.04 가상환경과 VS Code를 준비했습니다. 폴더를 만들고 이동하고 파일을 생성하는 리눅스 명령어를 직접 사용했습니다. 이후 ROS 패키지의 소스·설정·실행 파일을 다루기 위한 출발점입니다.
Python은 값의 자료형과 출력, 입력, 조건문, 반복문, 함수와 인자를 차례로 다뤘습니다. 4월 5일에는 리스트의 추가·삭제·정렬, 딕셔너리, 클래스와 상속, 클래스 변수와 인스턴스 변수, 모듈과 패키지로 확장했습니다.
ROS 노드는 메시지를 받았을 때 실행할 함수와 반복해서 유지할 상태가 필요합니다. 함수·클래스·자료구조를 먼저 다루면서, 뒤에 등장할 콜백과 노드 객체를 읽고 수정할 기반을 마련했습니다.

04.12–04.26 / NODE & TOPIC
움직임을 메시지로 표현하고 노드끼리 전달하기
ROS1 catkin · ROS2 colcon · Twist · publisher / subscriber
4월 12일에는 ROS1 Noetic 컨테이너를 만들고, VS Code의 Dev Containers와 X11 화면 설정을 다뤘습니다. turtlesim을 실행한 뒤 rospack·rosnode·rosrun·rostopic 명령으로 패키지와 노드, 토픽을 확인했습니다.
hello_ros 패키지를 catkin_make로 빌드하고 Twist 메시지를 보내 turtlesim을 움직였습니다. ROS2에서는 hello_ros2 패키지를 colcon으로 빌드했습니다. 같은 로봇 제어 개념이 서로 다른 빌드·실행 환경에서 어떻게 표현되는지 비교한 실습입니다.
4월 19일에는 simple_pub·simple_sub와 rqt의 토픽 발행 도구를 사용하고, ROS2의 message.launch.py와 ROS1의 message.launch를 작성했습니다. 4월 26일에는 다섯 노드를 연결하는 과제를 진행했습니다. 실제 mt.launch에는 mtpub·mtsub·mpub·msub·msub2가 함께 등록되어 있습니다.

04.26–05.10 / SERVICE & PARAMETER
요청·응답과 설정값을 나누어 다루기
서비스 서버·클라이언트 · 비동기 호출 · YAML
토픽으로 계속 보내는 데이터와, 요청을 보낸 뒤 응답을 받는 동작을 구분했습니다. 4월 26일에는 ROS1 서비스 서버·클라이언트, 스레드와 비동기 호출 예제를 작성했고, 5월 10일에는 ROS2 서비스 서버와 클라이언트를 다뤘습니다.
구체적인 과제는 turtlesim의 펜 색상을 바꾸는 change_color_client.py입니다. 코드는 turtle1/set_pen 서비스를 기다린 뒤 0.3초 주기로 RGB 값을 정하고 call_async로 요청을 보냅니다. 응답 완료 콜백에서 결과를 확인해 요청과 처리를 분리했습니다.

화면에 보이는 로봇과 물리적으로 움직이는 로봇
URDF · link / joint · collision / inertial · Xacro
5월 24일에는 ku_description 패키지에서 myfirst.urdf·origin.urdf·visual.urdf·physics.urdf를 작성하며 모델을 단계적으로 확장했습니다. link는 몸체, joint는 부품 사이의 관계로 다루고, origin을 바꾸었을 때 위치와 방향이 어떻게 달라지는지 확인했습니다.

05.31 / SLAM & MAP DATA
센서가 본 공간을 지도 데이터로 읽기
Cartographer · LaserScan · OccupancyGrid · 지도 저장
5월 31일에는 Gazebo의 TurtleBot3와 Cartographer를 연결하고, 키보드로 로봇을 움직이며 RViz2에서 지도가 채워지는 과정을 확인했습니다. 생성한 지도는 map_server 도구로 PGM 이미지와 YAML 설정 파일로 저장했습니다. Cartographer의 Lua 설정에서 스레드·해상도·IMU 관련 항목을 살펴보는 튜닝 설명도 진행했습니다.
라이브러리를 실행하는 데서 한 걸음 더 들어가 지도 메시지의 구조를 직접 다뤘습니다. publish_map.py는 해상도 0.1m, 너비 200칸·높이 100칸인 OccupancyGrid를 만들고, 셀 값을 바꾸어 발행하는 예제입니다. 0·100·-1과 같은 값이 지도에 어떻게 표현되는지 관찰할 수 있습니다.
scan_map.py에는 LaserScan 구독과 지도 발행의 뼈대가 있지만, 센서 데이터를 지도에 반영하는 update 함수는 구현 과제로 남아 있습니다. 이 부분은 완성된 SLAM 알고리즘이 아니라 센서 메시지와 지도 자료구조를 연결해 생각하는 연습으로 구분합니다.

06.07 / NAV2 & TF
저장한 지도에서 목표점을 찾아 순회하기
초기 위치 · Nav2 목표 · FollowWaypoints · 좌표 변환
6월 7일에는 지도를 저장한 뒤 Nav2를 실행하고, RViz2에서 초기 위치와 목적지를 지정했습니다. 경로가 정해진 뒤 장애물을 추가해 로봇의 경로와 움직임이 어떻게 바뀌는지 살펴보는 실습도 포함되어 있습니다.
patrol.py는 FollowWaypoints 액션 클라이언트입니다. map 좌표계의 위치와 방향으로 PoseStamped를 만들고, 목표의 접수·피드백·결과를 처리합니다. 이동 명령을 한 번 보내는 것을 넘어, 작업이 끝났는지 확인한 뒤 다음 목표로 넘어가는 순찰 프로그램으로 확장했습니다.
같은 날 dynamic_tf·tf_listener·follow_turtlesim도 작성했습니다. 좌표 변환을 발행하고 읽어 다른 대상의 상대 위치를 해석하는 연습입니다. 지도의 위치, 로봇의 위치, 센서가 측정한 위치를 함께 사용하려면 기준 좌표계를 구분해야 한다는 점을 실습으로 연결했습니다.

06.14–06.21 / HARDWARE & PERCEPTION
LIMO의 센서를 읽고 움직임의 조건 만들기
주행 모드 · SSH · ROS1 네트워크 · 카메라와 LiDAR
6월 14일에는 LIMO의 하드웨어와 주행 모드를 확인하고 조종기·teleop·SSH로 실제 기체를 움직였습니다. LiDAR를 사용해 교육장 지도를 만들고 저장하는 실습도 진행했습니다. 6월 21일에는 노트북과 LIMO의 ROS1 통신을 설정하고, 노트북에서 토픽을 확인한 뒤 원을 그리는 이동 노드를 작성했습니다.
카메라 실습의 follow_yellow_line.py는 압축 영상 메시지를 받아 아래쪽 20%를 관심 영역으로 사용합니다. HLS 색공간의 범위 마스크로 선을 찾고, 영상 중앙과 검출 위치의 차이를 gap 토픽으로 발행합니다. 실제 코드의 검출 기준은 마지막 행에서 찾은 선 픽셀의 왼쪽 끝입니다. 변수 이름만 보고 차선 중앙을 계산한다고 설명하지 않았습니다.
stop.py는 LaserScan의 거리·각도를 x·y 좌표로 바꾸고, 전방의 지정 영역에 점이 들어오면 정지 여부를 Bool 메시지로 보냅니다. 실습은 인식·판단·제어를 나눈 뒤 실제 트랙에서 잘 움직이도록 값을 조정하는 흐름이었습니다.

6월 28일에는 ROS1의 limo_gazebo_sim을 설치하고 URDF·launch에 namespace를 적용했습니다. 다른 패키지의 월드와 모델을 가져오고 바닥 이미지를 바꾸면서 실습 환경을 구성했습니다. 실습 문서에는 큰 메시 모델로 시뮬레이션이 느려질 때 차체 형상을 단순한 box로 바꾸는 조정도 기록되어 있습니다.
limo_application을 Gazebo에서 동작하도록 수정한 뒤 실제 LIMO에서도 동작을 시험했습니다. 센서 토픽과 이름 공간, 실행하는 launch가 달라질 때 각 노드가 제대로 연결되는지 확인하는 과정입니다.
7월 5일에는 limo_gmapping_simul.launch로 지도를 만들고 limo_navigation_simul.launch로 내비게이션을 연결했습니다. ROS1의 patrol_limo는 move_base 액션 서버에 목표를 보내고, 성공 콜백을 받으면 2초 뒤 다음 지점을 보냅니다. 마지막 지점 이후에는 처음으로 돌아가 순회를 이어가며, 같은 노드를 실기체에서도 실행했습니다.
ROS2 시뮬레이션 단계
Cartographer·Nav2와 FollowWaypoints 액션으로 지도와 순찰을 배웠습니다.
ROS1 LIMO 적용 단계
gmapping·move_base·patrol_limo로 기체 환경에 맞게 연결했습니다. 두 환경의 이름과 API를 구분해 기록했습니다.

자료와 기록
kuLimo의 doc/python.md·ros.md·simulation.md·limo.md와 실제 패키지 코드를 대조했습니다. 운영계획과 실제 진행이 다를 때 수업일지를 우선했으며, ROS1 move_base와 ROS2 Nav2, 실습용 코드와 완성 기능을 구분했습니다.
